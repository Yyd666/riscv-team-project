## 推荐与基线

项目定义如下：B0 为独立 GNU `size`/`readelf`/`objdump` 静态参考；B1 为固定 O2；B2 为固定 Os；B3 为通过正确性检查的 O0/O2/Os 穷举最小 `.text`；A1 为 B0 加 R001；A2 为 A1 加 R002。B0 是参考测量，不是自动归因；A1/A2 的规则输出也不构成编译 pass 的因果证明。

## 归因结果

24 个 O2→O0/Os 比较均有完整原始 ELF、符号表、节表和无别名数字反汇编证据。R001 重建函数编码字节变化，独立 GNU 字节误差为 0/24；R002 核对 `.text = kernel + outside`，覆盖率为 24/24。未知编码、缺失符号、非 `.text` 函数和证据冲突的拒判行为在独立负例中验证，但这些负例不计入正式 24 个正向比较分母。

编码分解是静态统计恒等式。报告不把 R001/R002 写成优化 pass 的因果解释，不推断动态指令数、目标周期、能耗或硬件性能。当前正式批次没有动态指令、周期或能耗测量。

## 失败、拒判和零收益

正式批次没有编译失败、QEMU 输出失败、超时或缺失程序。相对 O2 的零收益数为 0/12，相对 Os 的零收益数为 12/12；“零收益”指该比较的 `.text` 字节没有减少，不表示运行性能没有变化。独立负例产生 partial/unavailable 状态，用于验证拒判门控，不伪造为正式成功样本。

## 结论范围与未完成项

本批次支持的结论是：在固定 RV64GC/LP64D 基线、已登记的 12 个仓库内程序、3 个优化档位和 108 个输入用例中，所有配置通过，Os 在每个程序上达到三档 `.text` 穷举最小值，24 个 O2→候选比较的静态 GNU 字节核对和 R001/R002 证据核对均通过。

以下结论当前不受证据支持：对一般 C 程序的优化收益、编译 pass 因果作用、动态性能提升、硬件周期或能耗收益，以及留出集来源独立和未参与规则调试。12 个程序共享仓库作者账号和生成工作流；家族标签不重叠，但不能替代独立来源证据。`call_chain` 的任意 int32 输入也可能溢出，数值审计只覆盖登记输入。

最终验收仍需：

- 两个真实成功/失败或拒判路径的录屏；
- 官方资格、截止时间、署名和第三方来源核对；
- 可供团队审查的正式报告证据索引和材料归档；
- 对来源独立性和人员身份限制作出团队确认。

在上述条件满足前，`acceptance_ready` 保持 `false`。
