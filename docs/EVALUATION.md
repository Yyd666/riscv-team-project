评估摘要结构版本 0.2.0；`evaluate_attribution.py` 不满足自动门槛时仍保存诊断并返回 3，输入格式错误返回 2。旧摘要 0.1.0 不由新报告生成器接收。`acceptance_ready` 保持 false，因为自动脚本不能替代人工签署的金标准。

评估执行复用正式执行模块，保留实际工具版本、原始输出、登记与实现快照；运行和核验命令见 [评估执行与证据追溯](EVALUATION_EXECUTION.md)。草稿诊断与正式冻结评价分开记录，诊断记录不满足正式评估资格。

## 评估问题

1. 处理流程能否在同一环境正确编译、运行并核对全部登记输入？
2. 归因模块能否精确重建函数及 `.text` 的字节变化，并在证据不足时正确拒判？
3. 归因报告相对原始 `size + objdump` 输出增加了哪些可验证信息？
4. 固定配置推荐相对直接 O2、直接 Os 的结果如何，是否出现无收益或失败？

固定三档推荐等同于对通过配置求最小值，其结果应与穷举基线一致。不能声称比相同候选集的正确穷举结果更优。

## 语料分层与隔离

| 层次 | 内容 | 用途 | 当前状态 |
| --- | --- | --- | --- |
| 冒烟语料 | 现有 3 个源程序、9 组输入 | 编译/校验与异常处理流程 | 已登记 |
| 开发语料 | 求和、点积、阈值、直方图、游程统计、滚动哈希六个程序家族 | 规则开发与调试 | 六个不同家族已机器冻结，MIT 已登记；双人复核待完成 |
| 独立评估语料 | 校验和、查表/分支、函数调用、状态机、定点滤波、有界解析家族，目标至少 6 个程序 | 规则冻结后评价 | 六个不同家族已机器冻结，MIT 已登记；来源/家族及标注复核待完成 |
| 负例语料 | 符号缺失、编码截断、函数不在 `.text`、证据冲突等 | 拒判能力 | PR #18 已完成 6 类真实归因负例与独立 GNU 核验，不计为独立程序样本 |

源程序是独立样本单位；同一程序的多个 stdin 用例不能重复计为多个静态优化样本。开发集现已达到六个不同算法家族，留出集仍保持六个不同家族；正式效果结论仍需人工标注。

按程序家族及生成来源隔离开发集与评估集。更换函数名、输入规模或常量不构成独立程序。冻结评估清单及哈希后才执行最终评价；规则若使用留出集调试，须重新划分并发布版本。

每个程序登记源代码来源与许可、类型和数值范围、全部输入及独立预期输出。无符号模运算应明确，有符号溢出等未定义行为应排除。边界、零长度、混合符号、典型规模和固定种子随机输入按程序语义选择。

预期值来自独立数学实现或参考算法，不能仅复制 O0 结果。宿主未定义行为检查作为补充，不能单独证明跨架构等价。

## 对照基线与消融

- B0：GNU `size + objdump` 原始信息，无自动归因。
- B1/B2：固定使用 O2、固定使用 Os，仍执行同样的正确性检查。
- B3：穷举 O0/O2/Os 后在通过配置中按 `.text` 最小选择；本项目推荐应与其一致。
- A1：B0 加 R001；A2：A1 加 R002。后续编译诊断关联单列 A3，不将现成诊断工具的能力计为自研。

比较所有成功、失败和无收益项。不得只选推荐有效的程序，也不得以 O0 为唯一收益基准。

## 指标与统计单位

| 指标 | 定义 |
| --- | --- |
| 字节重建误差 | 预测字节变化与独立 ELF 计算变化的差值，支持样例要求为 0 |
| 规则有效率 | 经独立证据核验正确的规则输出 / 所有已验证状态的规则输出 |
| 解释覆盖率 | 成功解释的适用比较对 / 独立标注为适用的比较对 |
| 拒判率 | partial 或 unavailable 比较对 / 全部请求比较对，按原因分层 |
| 编译失败率 | 编译失败的配置数 / 实际尝试编译的配置数，工具缺失单独记录 |
| 用例失败率 | 输出、退出码或 stderr 不符的用例数 / 实际执行用例数；超时另列 |
| 配置通过率 | 该程序全部登记用例均通过的配置数 / 尝试配置数 |
| 体积变化率 | `(推荐 .text - 对照 .text) / 对照 .text`，对照失败或分母为零时缺失 |
| 穷举差额 | 推荐 .text 减 B3 最小 .text，固定三档推荐要求为 0 |

时间仅记录宿主诊断耗时与分析开销，不用于目标性能排名。动态指令数、周期与能耗保持缺失，直到有独立测量协议。

规则指标按规则和总体分别报告。分母为零时结果为缺失，不能记为 100%；`not_applicable` 保留原始数量，不静默移出总样本统计。全部拒判不能通过支持样例的精确归因验收。

## 标注与证据复核

1. 两位成员分别对符号范围、16/32 位编码、未知字节及节成员关系复核，再记录分歧和裁决。
2. 金标准来自原始字节及独立工具核对，不由待评估解析器生成。标注文件保存程序/产物哈希、规则版本、证据定位和复核人。
3. 正例和负例均覆盖；展示性 mock 不计为算法测试准确率或真实编译测试结果。
4. 报告给出原始计数、分母、逐程序结果及失败原因。后续启发式解释另行设置精确率、覆盖率、样本量和置信区间要求。
