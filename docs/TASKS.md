## 验收顺序

1. M0：ENV-01 → ENG-01/02/03/04 → CLI-01 → REPORT-01。完成基础流程，不等待 Web。
2. M1：ATTR-01 及对应规则、原始证据和负例检查。
3. M2：GOLD-01 与规则冻结 → EVAL-01 → REPORT-02 → DEMO-01。
4. API/UI 可并行开发，其完成状态不作为上述阶段的前置条件。

报告生成器属于实现任务，最终实验报告属于评估产物，两者分别登记，避免评估完成前要求最终报告完成。

## 环境与进度处理

mock 仅支持界面开发与契约联调。工具链故障时迁移至其他真实 Linux/WSL2 或明确授权的 Linux 云环境，并记录版本差异；没有可用真实环境时标记 M0 未完成。

交付范围按阶段记录。仅完成 M0 时，应将归因与独立评估列为待完成项。新增候选参数不得先于决策、版本和公共检查同步。

## 任务状态管理

每项任务登记主负责人、提交/PR、检查命令及证据位置。完成后更新 STATUS；范围或依赖变化同步需求与决策，历史验证记录保留。
