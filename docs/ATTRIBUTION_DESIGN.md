# RV64GC 代码体积变化归因设计 0.1.0

状态：R001/R002 归因引擎与 sidecar 已实现，真实 ELF 正负例和独立评估待完成。0.1.0 不自动识别对齐填充；没有 linker map 或等价对齐证据时 `known_padding_bytes=0`，不会仅凭 NOP 进行填充归类。策略配置见 [attribution-policy.json](../config/attribution-policy.json)，结果结构见 [attribution.schema.json](../contracts/attribution.schema.json)。

## 技术目标与贡献边界

核心模块面向 RV64GC，解释同一程序在不同编译档位下的代码体积变化，给出可复核的字节统计与证据位置。主要能力为函数编码分解、函数内外体积变化分离，以及证据不足时的明确拒判。

编译执行、用例校验与固定档位推荐构成基础流程。归因模块是拟开发的自研部分；技术新颖性与有效性须通过独立评估验证。现阶段不宣称获得优化收益或相对现有工具领先。

## 推荐对象与分析对象

- 推荐对象：静态链接后完整 ELF 中名称为 `.text` 的节。通过全部用例的配置按 `text_section_bytes` 升序排列，平局规则沿用编译基线。
- 诊断对象：当前版本固定为 `kernel` 函数。诊断与推荐分别输出，不能将整个 `.text` 的变化全部归因于该函数。
- 比较方向：候选配置减参考配置；参考配置为 O2。O2 未通过全部用例时，仍可推荐其他通过配置，但归因结果为 `unavailable`，原因为参考方案不可用。
- 分析前提：候选与参考来自同一实验，源码、输入、基线与工具链一致，且均通过该程序全部登记用例。

## R001：函数编码字节分解

设函数符号范围的机器码字节数为 C，识别的 16 位指令数为 N16，32 位指令数为 N32，未分类字节数为 U：

```text
N = N16 + N32
C = 2*N16 + 4*N32 + U = 4*N - 2*N16 + U
ΔC = 4*ΔN - 2*ΔN16 + ΔU
```

输出三个分量：`instruction_count_term_bytes = 4*ΔN`、`encoding_width_term_bytes = -2*ΔN16`、`unclassified_term_bytes = ΔU`。三者之和必须等于函数体积变化。

该分解是编码统计恒等式，说明指令数量与编码组成的变化，不能单独证明某个编译优化 pass 的因果效果。例如新增的压缩指令也可能来自控制流改变，而非原有指令的一对一压缩。

解析要求：

1. 从 ELF 符号表确定地址、大小和所属节，按地址范围读取原始字节，以实际编码判定宽度；反汇编使用基线规定的无别名、数字寄存器格式。
2. 标签和注释不计为指令；不完整编码、数据区、未知编码与无法确定边界的字节计入 U，不推测指令数量。
3. `known_padding_bytes` 是经证明的填充字节子集，仅作说明，不再次加入 C 或 ΔC。NOP 本身不足以证明属于对齐填充，需要汇编指令、链接映射等证据。
4. U 大于零时结果为 `partial`；缺失符号、函数边界无法确定或输入不符合比较前提时为 `unavailable`，不得输出完整解释。

## R002：函数内外体积变化分离

当 `kernel` 的地址区间完整位于 `.text` 内，定义 T 为 `.text` 字节数、K 为该函数区间字节数、O 为该节中其他字节：

```text
O = T - K
ΔT = ΔK + ΔO
```

`outside_kernel_delta_bytes` 包含其他函数、静态库、启动代码及节内填充的合计变化，不进一步推断其来源。需要细分时必须解析更多符号和链接信息；别名或重叠区间按地址并集统计，禁止重复求和。

函数不位于 `.text`、符号区间越界或重叠关系不明确时，R002 拒判，输出 `not_applicable` 及原因，整份结果最多为 `partial`。完整文件大小、`.text` 和函数大小分别保留原有定义。

## 解释证据与拒判

每项规则输出 `rule_id`、`status`、说明和 `evidence_ids`。证据记录类型、原始产物 SHA-256 和具体定位信息。R001 关联符号边界、原始编码与反汇编，R002 关联节表和符号表。纯文本结论没有证据引用时不计为已验证解释。

解释状态为 `verified`、`abstained` 或 `not_applicable`。结果状态为：

| 状态 | 条件 |
| --- | --- |
| `complete` | 比较前提成立，U 均为零，R001/R002 均适用且已验证 |
| `partial` | 比较前提成立且函数字节可核对，但存在未知字节或规则拒判 |
| `unavailable` | 比较前提不成立，或基本产物与边界不足以建立核对关系 |

该归因状态不替代运行正确性状态，也不改变原有编译推荐。禁止根据静态字节变化输出速度、周期或能耗结论。

## 编译诊断扩展

GCC 的 `-fopt-info` 和优化记录、LLVM 的 optimization remarks 可作为后续证据来源。它们已有优化诊断能力，自研价值应体现为诊断与 RV64GC 编码、符号和节变化的关联。[GCC 诊断说明](https://gcc.gnu.org/onlinedocs/gcc/Developer-Options.html#index-fopt-info)、[LLVM Remarks](https://llvm.org/docs/Remarks.html)

现有公共编译 flags 保持不变。后续辅助诊断编译使用独立目录；只有源码、工具链及目标 ELF 哈希与主实验匹配时，才能将其诊断绑定到该实验。否则仅作独立参考。格式不支持、源代码位置无法对应或证据冲突时拒判。

因果型解释须另设规则 ID、证据等级与标注评估，不能把 R001 的代数分量自动升级为 pass 因果解释。

## 验收要求

- 支持的 RV64GC 样例必须逐字节满足 R001、R002 恒等式；失败项不得标为完整解释。
- 覆盖编码比例变化、指令数量变化、整体/函数推荐不一致、未知字节、非 `.text` 函数及证据缺失场景。
- 实测时可从独立原始 ELF、符号表和节表重算结果；字节差额必须为零。
- 效果评价遵循 [EVALUATION.md](EVALUATION.md)，同时公布覆盖率与拒判率，不能通过全部拒判获得虚假的高准确率。
