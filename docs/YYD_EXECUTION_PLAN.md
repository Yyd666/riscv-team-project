# 编译执行模块实施计划

## 范围与完成条件

本计划覆盖任务板中 yyd 负责的 ENV-01、ENG-01、ENG-02、INTEG-01。SJS 的静态分析、归因、推荐、CLI、报告和评估模块保持原责任，不在执行模块内重复实现。

| 阶段 | 实施内容 | 完成证据 |
| --- | --- | --- |
| 1 | 固定 Python 执行记录类型、受限执行器接口和调用边界 | 类型定义、接口说明、输入拒绝检查 |
| 2 | Linux 工具探测、版本归档、真实单样例交叉编译与 QEMU 执行 | 工具版本、包清单、ELF 与输出哈希 |
| 3 | 非阻塞限额读取、超时/取消和进程组清理 | Linux 子进程及后代清理、双流限额、stdin/失败测试 |
| 4 | 登记请求、固定配置、全部用例、快照及证据目录 | 三程序三档共 27 次真实用例执行；独立重跑输出和 ELF 对照 |
| 5 | 自动化检查、CI、模块文档、任务状态及分支提交 | 公共检查、模块检查、实测证据清单、提交和检查链接 |
| 6 | 对接 SJS 分析/CLI、归因及金标准 | 对应实现存在后执行真实 M0/M1/M2 集成；双方独立复核记录 |

执行数据使用中间记录包，禁止伪装成完整实验 JSON。静态指标和全流程 passed 由后续分析/编排模块补充。缺工具、基础设施异常与总预算耗尽显式报错，已生成的诊断保留；失败不得回退 mock 或本机架构。

## 验证策略

- 受限执行器使用实际 Linux 进程验证超时、输出限额、退出码、取消与后代进程回收，不以函数实现镜像代替行为检查。
- 真实工具链对仓库登记程序执行 O0/O2/Os 全部输入，严格比较原始字节并保存版本、命令、源码/输入/配置/ELF 哈希。
- 全部配置在同一环境独立重复执行，比较确定性输出及 ELF 哈希；宿主耗时只用于诊断。
- 接口、任务状态、错误语义与文件归属同步文档；静态分析、归因、双人标注不存在时对应集成状态保持未完成。
