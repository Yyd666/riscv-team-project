# 项目范围与约束 v0.5

## 项目定义

RISC-V OptiPilot 面向 RV64GC 程序分析场景，提供可信语料的编译执行、用例校验、目标代码分析和有限配置推荐。自研模块的开发目标为函数级代码体积变化归因，详细定义见 [ATTRIBUTION_DESIGN.md](ATTRIBUTION_DESIGN.md)。

## 基础流程需求

1. 只接受仓库登记的单文件 C 样例及固定输入，不提供任意代码上传。
2. 按现有 O0/O2/Os 基线编译为 RV64GC/LP64D Linux 静态 ELF。
3. 使用 QEMU 执行全部登记用例，逐字节比较 stdout、stderr 与退出码。
4. 保留失败、超时、输出超限和工具缺失记录，通过全部用例的配置才参与推荐。
5. 以完整 `.text` 为推荐目标，单列 ELF 文件大小与 `kernel` 指标。
6. CLI 输出契约一致的 JSON、Markdown 报告及原始证据位置。

## 核心分析需求

1. 对同一实验中的 O2 与候选通过配置进行比较；参考失败时显式拒判。
2. R001 按 16/32 位编码与未知字节分解函数体积变化，差额必须为零。
3. R002 分离函数内外对 `.text` 变化的贡献，无法确定节成员关系时拒判。
4. 每项解释具备规则 ID、状态、产物哈希和证据定位。
5. 区分实测统计事实、未解释部分和后续因果型解释，不将代数分解解释为优化 pass 的因果证明。
6. 新增独立归因文件，保留原实验契约和编译基线，避免使现有客户端失效。

## 阶段与交付

- M0：3 个源程序、9 组输入、三档编译共 27 次真实执行；完成 CLI 和报告生成器。
- M1：实现 R001/R002，验证正例、负例、未知字节与整体/函数变化不一致的场景。
- M2：冻结开发规则与独立评估集，完成原始数据、标注与效果报告。
- M3：评估编译诊断关联、更多候选参数、动态指标或硬件验证，分别新增决策与协议。

M0 是基础流程交付，不等于核心归因模块完成。M1/M2 完成前，不在材料中将自研能力或技术效果写成已验证。FastAPI 与前端为可选增强，工具链故障通过其他真实 Linux 环境处理，mock 仅用于联调。

## 评估与结论边界

现有小型语料只用于流程检查。独立评估按源程序家族与生成来源隔离，输入数量不充当静态优化样本数。对比固定 O2、固定 Os、三档穷举及原始 binutils 输出，报告零收益、失败、覆盖率与拒判率，具体见 [EVALUATION.md](EVALUATION.md)。

固定配置推荐不得宣称优于相同候选集的正确穷举结果。归因的价值通过证据与解释质量评价，不使用目标加速、周期或能耗结论替代。

## 范围限制与变更

首版不包含自研 CPU/编译器、完整 ISA 仿真器、RV32/RVV、多用户服务、任意代码执行或 AI 自动改写源码。新 ISA、优化目标、候选参数或因果解释规则须记录决策并同步相应版本、契约及验证数据。

官方材料要求与截止时刻由参赛团队核对。阶段验收以真实完成状态为依据，未完成项目应列明限制。
