# 项目范围与约束 v0.1

建立日期：2026-10-24，工作时区 Asia/Shanghai。

## 项目定义

暂定名称：RISC-V OptiLab。项目面向 RISC-V 程序学习与开发场景，支持比较编译方案、校验程序输出、分析目标代码差异，并保存可复现的实验记录。

项目采用纯软件方案。名称、分工及后续研究内容可通过决策评审调整；功能实现与验证状态统一记录在 `docs/STATUS.md`。

## 首版功能需求

1. 从注册语料选择一个单文件 C 程序，读取固定输入，不接受任意上传或 shell 参数。
2. 在同一环境按 `-O0`、`-O2`、`-Os` 编译为 RV64GC / LP64D Linux 静态 ELF。
3. 使用 QEMU linux-user 执行该程序的全部登记用例，按预期 stdout、stderr 和退出码进行校验。
4. 展示 `.text` 字节数、整个 ELF 文件字节数、`kernel` 函数机器码字节数、静态指令及压缩指令数量。
5. 在全部用例通过的方案中，按 `.text` 字节数最小原则推荐编译配置，并标注静态体积依据。
6. 输出契约一致的 JSON 与 Markdown 报告，含命令、环境、哈希、原始运行结果和失败信息。
7. 前端提供编译方案、汇编及分析说明的对照视图。mock 模式显示演示标识，API 模式失败时报告错误。

## 范围限制

首版不包含自研 CPU 或编译器、完整 ISA 仿真器、RV32/RVV、多线程、浮点精度优化、AI 源码改写、任意用户代码执行、公网多人服务、账户、数据库及硬件验证。实验按单任务串行执行。

## 后续研究与评估

首版以编译分析与验证流程为交付目标，固定编译档位比较用于建立对照基线。后续研究方向包括面向 RISC-V 指令结构的可解释变化分析，以及正确性约束下的有限编译策略搜索。

改进效果须使用预先确定的独立评估语料验证，至少对比 `-O2`、`-Os` 与固定候选的穷举结果，并报告搜索成本、失败率及无收益情况。体积、执行时间、周期与能耗结论应分别具有对应测量依据。

技术说明应列明第三方工具及其用途，自研工作应对应具体的分析、校验、策略、接口实现与实验记录。
