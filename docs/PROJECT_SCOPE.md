# 项目范围与约束 v0.2

建立日期：2026-10-24，工作时区 Asia/Shanghai。

## 项目定义

项目名称：RISC-V OptiPilot。项目面向 RV64GC 程序开发与教学场景，提供正确性约束的编译配置搜索、目标代码分析、可解释推荐和可复现实验记录。系统先验证正确性，再允许方案进入比较和推荐。

## 首稿交付目标

2026-11-08 前交付一个可演示的纯软件 MVP：

1. 从注册语料选择一个单文件 C 程序，读取固定输入，不接受任意上传或 shell 参数；
2. 生成 O0、O2、Os 和少量安全候选配置；
3. 在同一环境编译为 RV64GC / LP64D Linux 静态 ELF；
4. 使用 QEMU 执行全部登记用例，校验 stdout、stderr 和退出码；
5. 记录编译失败、运行超时、输出不符和工具缺失等失败原因；
6. 分析 ELF 文件、.text、kernel 函数机器码和静态指令组成；
7. 计算正确性可行集与体积/耗时诊断的 Pareto 前沿；
8. 根据体积优先或性能诊断优先输出推荐方案；
9. 生成契约一致的 JSON 与 Markdown 实验报告，保留命令、版本、哈希和原始运行结果；
10. 通过 CLI 或前端完成一条可录制的演示流程。

## 核心创新

- 正确性门控：方案必须通过全部登记用例后才参与推荐；
- 有限策略搜索：在可追踪候选配置集合中自动组合和比较，记录搜索空间、成本和失败率；
- 可解释推荐：用指标变化、函数反汇编和失败原因解释方案选择；
- 可复现实验：源码、输入、配置、工具版本和输出均保存哈希。

这些机制构成系统方法创新，技术说明不得将其表述为自研编译器或通用最优编译器。

## 范围限制

首稿不包含自研 CPU、自研编译器、完整 ISA 仿真器、RV32/RVV、多线程、浮点精度优化、AI 源码改写、任意用户代码执行、公网多人服务、账户、数据库和硬件验证。

## 评估要求

改进效果至少使用独立评估集验证，并报告与 O2、Os 的对比、搜索空间、编译成本、失败率、无收益方案和适用范围。所有结论必须说明比较条件，不能把单次宿主耗时解释为目标硬件性能。
