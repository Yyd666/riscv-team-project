# 决策记录

本文采用架构决策记录（ADR）形式，记录工程基线及其变更依据。建立日期：2026-10-24。历史 ADR 编号保持稳定；新增决策追加编号。

## ADR-001：纯软件方案与可信语料

项目采用纯软件方案，首版覆盖编译、仿真、输出校验及分析报告，执行范围限定为已登记的可信语料。CPU、自研编译器与任意代码执行平台不纳入首版。

## ADR-002：RV64GC + LP64D + Linux 静态链接

选择 GNU Linux 交叉工具链与 QEMU 用户态，减少裸机启动、sysroot 和硬件依赖。显式固定 ISA/ABI、CPU 型号与 flags；工具版本通过真实实验记录。

## ADR-003：O0/O2/Os 基线与有限候选配置推荐

初稿保留 O0、O2、Os 作为机器基线。正确性通过全部登记用例的配置，才参与按 .text 静态代码体积进行的有限候选配置推荐。宿主 wall_time_ms 仅用于超时和执行异常诊断，不作为性能排名依据。

## ADR-004：接口契约与并行开发

前后端依据统一契约并行开发。UI 使用带标识的 mock，API 模式失败时返回错误。公共基线保存在 main，成员通过 merge 同步。

## ADR-005：JSON 证据与 Markdown 文档

结构化实验记录使用 JSON，报告使用 Markdown。代码许可证由作者确认后添加。

## ADR-006：正确性门控与可解释分析

演示流程必须同时展示通过配置、失败配置、关键静态指标变化和函数级反汇编差异。推荐结果链接到原始命令、工具版本、源码/输入/配置哈希和运行输出。该决策描述流程和工具集成创新，不宣称自研编译优化算法。

## ADR-007：CLI 是首稿必需交付，API/UI 为可选增强

首稿验收以真实 Linux/WSL2 编译、QEMU 执行、正确性校验、静态分析、CLI 和 JSON/Markdown 报告为必需条件。FastAPI 和前端不作为 CLI 交付的前置依赖。

## ADR-008：mock 不替代核心实测

mock 仅用于界面开发和接口联调。工具链故障时应切换到另一真实 Linux/WSL2 或 Linux 云环境，并记录环境差异；若没有可用真实环境，必须明确标记 RISC-V 实测未完成。

## 决策变更流程

变更时新增 ADR 编号，记录问题、方案选择、替代方案、影响文件、版本迁移及验证结果。不得重用已有编号或改变历史 ADR 的原始含义。
