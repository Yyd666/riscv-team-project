# 决策记录

本文采用架构决策记录（ADR）形式，记录工程基线及其变更依据。建立日期：2026-10-24。

## ADR-001：纯软件方案与可信语料

项目采用纯软件方案，首版覆盖编译、仿真、输出校验及分析报告，执行范围限定为已登记的可信语料。CPU、自研编译器与任意代码执行平台不纳入首版。项目名称及后续研究内容通过决策评审调整。

## ADR-002：RV64GC + LP64D + Linux 静态链接

选择 GNU Linux 交叉工具链与 QEMU 用户态，减少裸机启动、sysroot 和硬件依赖。显式固定 ISA/ABI、CPU 型号与 flags；工具版本通过真实实验记录。代价是静态库会影响整体 `.text`，所以另列 kernel 指标。

## ADR-003：固定 O0/O2/Os；按体积推荐

O0 用于基础观察，O2/Os 用于优化配置对照。首版采用固定候选配置，以全部用例通过为前提，选择 `.text` 最小的方案；并列时依次优先 O2、Os、O0。宿主耗时仅用于诊断，后续编译策略搜索独立评估。

## ADR-004：接口契约与并行开发

前后端依据统一契约并行开发。拟议分工为 yyd 负责核心引擎、sjs 负责界面，任务登记结果为最终依据。UI 使用带标识的 mock，API 模式失败时返回错误。公共基线保存在 `main`，成员通过 merge 同步。业务依赖由首个实现 PR 锁定，基础检查的直接依赖已固定版本。

## ADR-005：JSON 证据与 Markdown 文档

开发约定与报告草稿使用 Markdown，结构化实验记录使用 JSON。Word/PDF 按专项工作流或明确的格式导出请求生成。项目代码许可证由作者确认后添加。

## 决策变更流程

变更时新增 ADR 编号，记录问题、方案选择、替代方案、影响文件、版本迁移及验证结果。历史 ADR 保留，并注明替代关系。接口破坏性变更、ISA/ABI 调整、优化目标变更及源码上传功能，均须先完成决策记录。
