# 决策记录

本文采用架构决策记录（ADR）形式，记录工程基线及其变更依据。建立日期：2026-10-24。

## ADR-001：纯软件方案与可信语料

项目采用纯软件方案，首版覆盖编译、仿真、输出校验及分析报告，执行范围限定为已登记的可信语料。CPU、自研编译器与任意代码执行平台不纳入首版。

## ADR-002：RV64GC + LP64D + Linux 静态链接

选择 GNU Linux 交叉工具链与 QEMU 用户态，减少裸机启动、sysroot 和硬件依赖。显式固定 ISA/ABI、CPU 型号与 flags；工具版本通过真实实验记录。

## ADR-003：正确性约束的有限策略搜索

问题：仅比较 O0、O2、Os 难以体现优化推荐的创新性，也无法回答候选配置在正确性约束下的适用范围。

决策：保留 O0/O2/Os 作为基准组，新增少量安全候选配置形成有限搜索空间。每个候选方案必须通过全部登记用例，才进入体积和执行诊断比较。系统记录搜索空间、编译成本、失败率、无收益方案和推荐理由。

替代方案：直接实现自研编译器或使用机器学习搜索。前者无法在首稿周期内交付，后者需要独立评估集和更长实验周期，保留为后续研究。

影响：需要扩展配置模型、结果 Schema、报告模板和验收用例，相关任务见 docs/TASKS.md。

## ADR-004：正确性门控与可解释推荐作为产品主线

演示流程必须同时展示通过方案、失败方案、关键指标变化和函数级反汇编差异。推荐结果链接到原始命令、工具版本、源码/输入/配置哈希和运行输出。

## ADR-005：接口契约与并行开发

前后端依据统一契约并行开发。UI 使用带标识的 mock，API 模式失败时返回错误。公共基线保存在 main，成员通过 merge 同步。

## ADR-006：JSON 证据与 Markdown 文档

结构化实验记录使用 JSON，报告使用 Markdown。代码许可证由作者确认后添加。

## 决策变更流程

变更时新增 ADR 编号，记录问题、方案选择、替代方案、影响文件、版本迁移及验证结果。
