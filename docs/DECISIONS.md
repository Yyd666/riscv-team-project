# 决策记录

本文采用架构决策记录（ADR）形式，记录工程基线及其变更依据。建立日期：2026-10-24。历史 ADR 编号保持稳定；新增决策追加编号。

## ADR-001：纯软件方案与可信语料

项目采用纯软件方案，首版覆盖编译、仿真、输出校验及分析报告，执行范围限定为已登记的可信语料。CPU、自研编译器与任意代码执行平台不纳入首版。

## ADR-002：RV64GC + LP64D + Linux 静态链接

选择 GNU Linux 交叉工具链与 QEMU 用户态，减少裸机启动、sysroot 和硬件依赖。显式固定 ISA/ABI、CPU 型号与 flags；工具版本通过真实实验记录。

## ADR-003：O0/O2/Os 基线与有限候选配置推荐

初稿保留 O0、O2、Os 作为机器基线。正确性通过全部登记用例的配置，才参与按 .text 静态代码体积进行的有限候选配置推荐。宿主 wall_time_ms 仅用于超时和执行异常诊断，不作为性能排名依据。

## ADR-004：接口契约与并行开发

前后端依据统一契约并行开发。UI 使用带标识的 mock，API 模式失败时返回错误。公共基线保存在 main，成员通过 merge 同步。

## ADR-005：JSON 证据与 Markdown 文档

结构化实验记录使用 JSON，报告使用 Markdown。代码许可证由作者确认后添加。

## ADR-006：正确性门控与可解释分析

演示流程必须同时展示通过配置、失败配置、关键静态指标变化和函数级反汇编差异。推荐结果链接到原始命令、工具版本、源码/输入/配置哈希和运行输出。该决策描述流程和工具集成创新，不宣称自研编译优化算法。

## ADR-007：CLI 是首稿必需交付，API/UI 为可选增强

首稿验收以真实 Linux/WSL2 编译、QEMU 执行、正确性校验、静态分析、CLI 和 JSON/Markdown 报告为必需条件。FastAPI 和前端不作为 CLI 交付的前置依赖。

## ADR-008：mock 不替代核心实测

mock 仅用于界面开发和接口联调。工具链故障时应切换到另一真实 Linux/WSL2 或 Linux 云环境，并记录环境差异；若没有可用真实环境，必须明确标记 RISC-V 实测未完成。

## ADR-009：整体推荐与函数诊断分离

现有编译基线及实验契约保持 0.1.0，完整 `.text` 仍为推荐目标。`kernel` 仅作为函数诊断对象，单独记录函数内外变化；不得把整体体积变化全部归因于该函数。

## ADR-010：编码归因、证据与拒判

归因契约独立版本化为 0.1.0。R001 定义指令数量、16 位编码及未知字节的精确统计分解；R002 定义函数内外的 `.text` 分解。两者属于可核对的统计事实，不能单独构成 pass 因果证明。证据不足时拒判或标记部分解释，填充字节按子集处理。

## ADR-011：独立评估与对照

源程序是评估单位，开发与留出语料按程序家族和来源隔离。对照固定 O2、固定 Os、三档穷举与原始 binutils，归因分别评估 R001 及 R001+R002。规则有效率、覆盖率、拒判率和零收益结果共同发布。扩展语料与实际效果仍待建立。

## ADR-012：分阶段验收与报告依赖

M0 验收真实编译/运行、静态指标、CLI 和报告生成器；M1 验收归因规则与证据；M2 验收冻结语料、独立评估及最终报告。先实现生成器再评估，最终报告由评估产物生成。API/UI 保持可选。

## ADR-013：按工作量分配与独立模块开发

必需交付的预计工作量调整为 sjs 60%、yyd 40%，不按任务数或代码行数分配。yyd 主责工具链、编译运行、正确性与集成复核；sjs 主责 ELF/编码分析、推荐、归因、CLI 编排、报告及评估。具体权重见 TASKS，可选 API/UI 不计入必需交付比例。

原分工将编译、分析、CLI 和归因集中于同一成员，形成较长串行路径。调整后以进程内执行记录包和既有实验/归因契约划分边界，分析器可独立读取真实 ELF，报告及 CLI 可使用明确标识的测试输入开发。文件责任按模块划分，包入口由 sjs 维护，执行类型和受限执行器由 yyd 维护，首批实现 PR 固定内部签名并交叉复核。

模块独立开发和独立 PR 不表示全流程验收通过；M0/M1/M2 的真实集成依赖及金标准双人复核保持。编译基线、公开 Schema 和指标含义不变，无公开契约版本迁移。同步 TASKS、HANDOFF、ARCHITECTURE、CONTRIBUTING 和 STATUS，并执行公共检查与文档差异检查。

## ADR-014：执行记录包与可复用受限执行器

执行模块首先独立实现，不创建与 SJS 产品 CLI 重复的入口。`experiment_session` 持有全流程互斥与共享 120 秒 deadline；`execute` 在该 session 内返回类型明确的执行记录包。编译和全部登记用例使用快照与严格字节比较，成功状态为 `execution_passed`，不提前生成静态指标或完整实验 `passed`。

工具执行采用 Linux 非阻塞管道、独立进程组和逐流限额，正常/异常结束均清理后代。固定系统工具和 C locale，归档版本、实际参数、哈希和原始输出。执行记录包为内部数据边界，公开实验/归因 Schema、编译选项与指标定义保持 0.1.0。

INTEG-01 先建立原始执行证据和最终结果投影检查；独立 ELF 指标、归因及双人金标准复核等待相应模块，不以合成投影测试替代实际集成。新增 Linux CI 执行行为检查和两轮真实语料运行，并上传运行产物。接口、任务状态及复现命令同步 EXECUTION、ARCHITECTURE、STATUS 与实施计划。

## ADR-015：评估语料采用范围明确的 MIT 许可

2026-10-27：12 个仓库自编评估程序及登记输入/预期输出采用 MIT，原文置于 `evaluation/LICENSE`，范围和仓库引入提交置于 `docs/CORPUS_LICENSE.md`。语料版本提升至 `0.1.1`，登记许可文件 SHA-256；执行前验证许可，导出的登记与实现快照携带原文。该范围不对仓库其他代码、系统库、工具链或第三方二进制改授许可。

许可元数据变化不修改程序和测试资产，也不修改历史 `0.1.0` 批次、ELF、sidecar 或标注。历史资产按相同字节/哈希关联后续授予，复核使用被标注批次自身清单；新版本运行产生新批次。相对于继续保留许可未定或对整个仓库统一授予，限定范围可满足语料共享并明确第三方边界。编译基线、实验/归因契约和指标定义保持原版本；双人成员独立复核要求不变。

## 决策变更流程
