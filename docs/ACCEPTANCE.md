# 分层验收清单

各阶段分别验收。mock 和契约检查不计为真实引擎或算法评估结果；API/UI 未完成不影响 CLI 与归因模块验收。

## M0：基础流程

- [ ] 记录真实 Linux 环境、工具链、包清单、完整命令与版本。
- [ ] RISC-V ELF 的架构与属性符合 RV64GC/LP64D 基线。
- [ ] 3 个程序、9 组输入、3 个档位共 27 次执行均有原始记录。
- [ ] stdout、stderr 和退出码逐字节符合独立预期；故障注入可触发明确失败。
- [ ] 编译、运行、分析均有超时与输出限额，取消及失败后回收进程组。
- [x] CLI 的参数、退出码和原子保存语义符合契约。
- [ ] 通过全部用例的配置按完整 `.text` 推荐，与独立三档穷举结果一致。
- [x] JSON 与 Markdown 来自同一实验记录，源代码、输入、配置和产物可按哈希追溯。
- [ ] 同一环境连续执行两次，确定性输出与静态指标一致；宿主时间单独记录。

## M1：归因模块

- [x] R001 能按实际编码重建函数字节数，三个变化分量之和等于函数体积变化。
- [x] R002 能核对 `.text = kernel + outside`，符号区间与节成员关系有原始证据。
- [ ] 已覆盖整体体积减少但 kernel 变大的情况，报告分别说明。
- [ ] 已覆盖未知编码、符号缺失、非 `.text` 函数和证据冲突，状态与拒判原因正确。
- [ ] 每条已验证规则引用实际存在的产物及定位，缺失证据不得标为完整解释。
- [ ] 对齐填充作为子集处理，未重复计算，也未仅凭 NOP 断言为填充。
- [ ] 原实验 JSON 和独立归因 JSON 通过结构及语义校验，归因文件与实验哈希关联。
- [ ] 统计归因未被表述为 pass 因果证明、动态执行减少或性能提升。

## M2：独立评估与材料

- [ ] 开发/留出语料按程序家族及来源隔离，冻结清单与哈希，目标数量与实际数量分别公布。
- [ ] 原始字节与符号边界经过独立复核，标注不由被评估解析器直接生成。
- [ ] 逐程序比较固定 O2、固定 Os、三档穷举、原始 binutils 与归因模块。
- [ ] 公布字节误差、规则有效率、覆盖率、拒判率及失败/零收益结果，并明确分母。
- [ ] 在独立环境复现并记录差异；环境未锁定或未重跑时明确限制。
- [ ] 最终报告只引用可访问的实测证据，演示包含实际成功、失败及拒判场景。
- [ ] 官方材料、截止时刻、资格、署名和第三方来源经团队核对。
